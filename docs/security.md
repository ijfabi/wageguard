# Security

The OWASP Application Security Verification Standard served as the checklist while building this. Everything in the table below exists and has a test or scan behind it. The gaps are listed separately.

## What needs protecting

- People's pay data: their shifts, payslip amounts and job details.
- Password hashes and session tokens.
- The award rule sets and completed audits. If either could be quietly altered, results would change without anyone noticing.
- Uploaded CSV timesheets.

Untrusted input arrives from the browser at the API, and the API is the only thing that talks to PostgreSQL. CI runs on GitHub-hosted runners. Redis is provisioned but not used yet.

## Threats and what stops them

| Threat                                    | Control                                                                                                                                                                                                                 | How it's checked                                                                                                                     |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Password guessing and credential stuffing | argon2id hashing (19 MiB, 2 passes), a stricter rate limit on sign-in, and the same message and similar timing for an unknown email or a wrong password                                                                 | `auth.test.ts`, `platform.test.ts`                                                                                                   |
| Stolen sessions                           | 256-bit random tokens, stored only as SHA-256 hashes. Cookies are HttpOnly and SameSite=Strict, and Secure with the `__Host-` prefix in production. Sessions can be revoked on the server and expire after a fixed time | `auth.test.ts`: a stolen cookie stops working after sign-out, and expired sessions are rejected                                      |
| Cross-site request forgery                | SameSite=Strict, plus an origin check on every state-changing request (`Origin` allow-list and `Sec-Fetch-Site`)                                                                                                        | `platform.test.ts`                                                                                                                   |
| Reading or changing someone else's data   | Every query is scoped to the signed-in user, and other people's objects return 404. Composite foreign keys and triggers stop ownership from changing even if the application is bypassed                                | `security.test.ts` covers every object route, list endpoints, cross-user writes and direct database writes                           |
| Tampering with rule data                  | Rules are validated on load, fingerprinted with SHA-256 (checked at startup and in CI) and frozen in memory                                                                                                             | Unit tests, CI                                                                                                                       |
| Tampering with completed audits           | The snapshot is stored once, and a database trigger blocks UPDATE and DELETE. Deleting an account is the only way to remove audits, and it goes through a flag that only lasts for that transaction                     | `audits.test.ts`                                                                                                                     |
| Duplicate or replayed submissions         | An `Idempotency-Key` with a unique index, plus a hash of the request so a reused key with a different body is refused                                                                                                   | A 10-way concurrency test. Benchmark E repeats it with 50 concurrent requests and under failures                                     |
| Injection                                 | Parameterised queries throughout, strict schemas that reject unknown fields, allow-listed sort options and validated cursors                                                                                            | `security.test.ts`                                                                                                                   |
| Hostile CSV files                         | Size limits (256 KiB, 500 rows, 1 KiB per row), an exact header, every cell checked against a pattern (spreadsheet formulas are rejected), and all-or-nothing imports                                                   | `shifts.test.ts`, 11 malformed cases                                                                                                 |
| Overload                                  | Rate limits, a 512 KiB JSON body limit, at most 200 shifts and 10 breaks per calculation, and at most 100 items per page                                                                                                | Tests on each limit                                                                                                                  |
| Database outages                          | Requests fail within 3 seconds with `503` and `Retry-After` instead of hanging, and the API recovers by itself                                                                                                          | `error-filter.test.ts`, Benchmark E                                                                                                  |
| Leaking details in errors                 | One error format. Unexpected errors return a generic 500, with the details only in the logs, and the framework header is removed                                                                                        | `platform.test.ts`                                                                                                                   |
| Leaking data into logs                    | Request bodies are never logged. Cookie and authorization headers are redacted, query strings are dropped, and event records hold IDs and codes only                                                                    | `auth.test.ts` checks events contain no email                                                                                        |
| Leaking data into telemetry               | Telemetry is off unless configured. Custom attributes are allow-listed. A span processor strips client addresses, user agents and query strings. No headers, bodies or SQL parameters are captured                      | `telemetry.test.ts`, plus a manual check against a collector ([observability](observability.md))                                     |
| Clickjacking and content injection (API)  | helmet with `default-src 'none'`, `frame-ancestors 'none'`, `nosniff` and `X-Frame-Options`                                                                                                                             | Headers checked in tests                                                                                                             |
| Cross-site scripting (web app)            | A fresh nonce on every page. Only scripts carrying it can run (`'strict-dynamic'`, no `'unsafe-inline'` or `'unsafe-eval'` in production). React escapes output, and nothing uses `dangerouslySetInnerHTML`             | `access.spec.ts` checks the header, that every script has the nonce, that it changes per request, and that pages raise no violations |
| Open redirects after sign-in              | `?next=` must be a path on this site. Control characters, `//` and backslashes are rejected                                                                                                                             | Unit and end-to-end tests                                                                                                            |
| Passwords in URLs                         | The sign-in, sign-up and delete-account forms use POST, so even a submission before JavaScript loads can't put a password in the address bar                                                                            | End-to-end test with JavaScript turned off                                                                                           |
| Exported reports                          | Built only from the owner's stored snapshot, behind the same ownership checks, sent with `Cache-Control: no-store`, and every export is recorded                                                                        | The ownership sweep includes the PDF route                                                                                           |
| Denying an action happened                | `audit_events` records registration, sign-ins (successful and failed), sign-outs, imports, new audits, report exports and account deletion                                                                              | Tests per event                                                                                                                      |
| Supply chain                              | Exact versions and a lockfile. `pnpm audit` (high and above), a gitleaks scan over the full history, and a Trivy scan of both images run in CI. GitHub Actions are pinned to commit hashes                              | CI                                                                                                                                   |
| Secrets in the repository                 | Configuration only comes from the environment, and `.env` is git-ignored. A bad configuration is reported by variable name, never by value                                                                              | Startup validation, gitleaks                                                                                                         |
| Keeping data after an account is closed   | `DELETE /auth/me`, with the password re-entered, removes every row the user owns, including audits                                                                                                                      | `security.test.ts`                                                                                                                   |
| Misleading results                        | Anything the engine can't fully verify is marked "needs review" or "not supported" instead of guessed, and a partial calculation is never shown as a match                                                              | Engine and API tests                                                                                                                 |

## Known gaps

- **Email enumeration.** Registration tells you whether an email is already taken (`409 EMAIL_TAKEN`). The sign-up rate limit slows down anyone probing, but there's no email verification.
- **No account recovery or second factor.** There's no two-factor sign-in, password reset or account lockout. Rate limiting is the only brake on brute force.
- **Rate limits are per process.** The counters live in memory, so they're only correct with one API instance.
- **Encryption at rest.** This would come from the hosting platform (encrypted database storage, for example). Uploaded files aren't stored. Nothing is deployed yet.
- **Inline styles in the web app.** The content security policy still allows inline styles, because the UI libraries set them at runtime. Scripts are nonce-only.

## Dependency exceptions

`pnpm audit --audit-level high` runs in CI, and both container images are scanned with Trivy.

New releases normally wait two weeks before they're adopted ([ADR 0006](adr/0006-toolchain-versions.md)). A security fix is the exception. On 24 October 2026, CI's dependency audit flagged GHSA-q7qp-rjg7-q26m (high: denial of service in `multer`) in the version that `@nestjs/platform-express` 12.2.0 pins. The API never handles file uploads, so the flaw couldn't be reached. The vulnerable code was still in the production image, though, and the fixed `multer` 2.5.0 has the same dependencies as before. So `pnpm-workspace.yaml` forces 2.5.0 through `overrides`, two days after its release. Remove the override once NestJS ships with 2.5.0 or later.

Any advisory that's accepted rather than fixed is listed in `pnpm-workspace.yaml` (`auditConfig.ignoreGhsas`) and explained here.

| Advisory                                                                        | Package                                                                                                  | Why it's accepted                                                                                                                                                              | When to revisit                                             |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| GHSA-vfj7-8cjw-p6xm (high: denial of service from deeply nested brace patterns) | `braces` 3.0.3 and earlier, pulled in by `@next/eslint-plugin-next` through `fast-glob` and `micromatch` | No fixed version exists. It only runs inside the linter, on file patterns written in this repository, never on user input, and it isn't in either runtime image (Trivy checks) | When `braces` is fixed, or the plugin stops depending on it |

## House rules

- Synthetic data only. Real employee data never goes into this repository or its databases.
- Nothing in the calculation calls an external service or an AI model.
